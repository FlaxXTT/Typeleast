制作扩展

一个 JSON 文件，就是一个扩展。

不用写代码。用任何文本编辑器写好，先在自己的 App 里试装，满意了再提交到官方目录。

五步做好

  1. 选类型，起 id。词库还是风格？id 写成 发布者.名字，例如 yourname.web-terms。
  2. 复制下面的模板。填好中英文名字和说明、作者、许可。
  3. 写内容。词库写 terms（需要时加 aliases）；风格写 instructions。
  4. 保存为 <id>.typeleast-plugin。UTF-8 编码，最大 256 KiB。
  5. 在 App 里试装。「扩展」→「导入插件文件…」，看安装前的预览，再实际听写几句，确认效果。

模板

词库（第 2 版，带读音提示）
风格

两个模板都能通过 App 的检查。不需要读音提示时，把词库的 formatVersion 写成 1 并删掉 aliases。

字段规则

不接受未知字段；超过限制会被直接拒绝，不会截断。

字段规则
format / formatVersion固定写 "typeleast-plugin"；版本为 1，或带读音提示的词库用 2。
id发布者.名字，小写字母、数字和连字符，每段 1–32 个字符。官方目录里的文件名必须是 <id>.typeleast-plugin。
version主.次.修订，如 1.2.0，不带前导零。每次更新都要调大。
type"dictionary"（词库）或 "style"（风格）。
name / description都要有 zh-Hans 和 en 两种语言。名字最多 40 字，说明最多 200 字，都只能一行。
author显示名，最多 60 字。
licenseSPDX 标识，如 CC0-1.0、MIT、CC-BY-4.0，或 LicenseRef-…。
homepage可选，只接受 https:// 开头的地址，最多 200 字符。
terms词库专用。1–2000 个，每个最多 120 字，不分大小写不能重复。只写正确写法，不能写「听成=写法」。看起来像密钥的内容会被拒绝。
aliases仅第 2 版词库，可选，最多 200 条。每条有 heard（被听错的写法，最多 80 字）、term（必须和 terms 里某一项完全一致）、cues（1–8 个语境词），可选 blockers（最多 8 个排除词）。语境词每个最多 40 字。
instructions风格专用。非空纯文本，最多 8 KiB。

写词库的要点

  • 只收真实、常用、容易被识别错的写法。普通词不用放。
  • 大小写按官方写法：GitHub、macOS、Node.js。
  • 读音提示只是候选：当前这句话里出现 heard，同一句还出现某个 cues，且没有 blockers 时，才会提示模型。
  • 语境词要具体。和普通英语词同形的专名（如 cloud 和 Claude），要用 blockers 排除普通用法，或干脆不加提示。
  • 用户自己的词典永远优先；所有启用的词库合计最多 10000 个词、1000 条读音提示。

写风格的要点

  • 只写写法和格式：语气、段落、列表、标点、称呼。
  • 越短越好。选中后，每次自然整理和精简整理请求都会带上这段说明。
  • 风格不能添加事实、删掉说话内容或改变输出格式；整理结果仍会经过原有的事实校验，不通过就退回原来的结果。
  • 不要求输出链接、命令、联系方式或用户数据，也不要求忽略原有规则。
  • 翻译和提示词 Beta 不使用风格。

发给模型的是什么

类型随整理请求发送额外费用
词库只有和本次话语相关的术语和读音提示；无关的留在本机。不多调用模型。
风格选中后，整段说明随每次自然整理、精简整理请求发送。不多调用模型；每次请求多一些 token。

插件不运行代码。它不能联网、不能读文件，也不改变本机的语音识别；只是给整理模型多一些写法上的参考。

提交扩展

放进官方目录，
让更多人用上。

每个提交都由维护者人工审核。合并后官网自动部署，几分钟内就会出现在所有人的插件市场里。

提交要求

  • 文件能通过检查：在仓库根目录运行 node market/build-catalog.mjs 不报错。
  • 中英文名字和说明齐全，作者和许可写清楚；许可必须允许再分发。
  • 一个插件只做一件事，名字和说明如实描述内容。
  • 不含人名、内部项目名、联系方式、密钥或任何不该公开的内容。
  • 词库：词是真实、常用的写法；读音提示有依据，语境词足够具体。
  • 风格：只涉及写法和格式；不要求输出链接、命令、联系方式或用户数据，不要求忽略原有规则。
  • 更新已收录的插件时，调大 version。

提交方式

  1. Fork GitHub 仓库。
  2. 把文件放进 market/plugins/，文件名用插件的 id。
  3. 在仓库根目录运行 node market/build-catalog.mjs，它会检查文件并重新生成 catalog.json。
  4. 开一个 PR，写明用途、内容来源和许可。
  5. 维护者审阅后合并；官网部署完成，插件就会出现在 App 的插件市场里。

插件安全吗？

插件只是数据，不运行代码。安装前会显示全部内容；官方目录里的插件经过人工审核，从文件导入的会标为未审核。

会多花钱吗？

不会多调用模型。风格说明会让每次整理请求多一些 token；词库只发送本次相关的词。

为什么我的 App 里没有插件市场？

插件从 TypeLeast 1.20 开始支持。请到首页下载最新版本。

可以只给自己用吗？

可以。做好的文件直接在 App 里「导入插件文件…」，不用提交。也可以发给同事，他们同样从文件导入。
