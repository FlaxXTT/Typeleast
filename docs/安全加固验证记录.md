# 安全加固验证记录

日期：2026-10-19。基于 PR #17 的翻译、语言变体和活动热力图分支。此记录只说明本轮证据，不承诺没有缺陷或泄漏。

## 改动

1. Mac 构建开启 Hardened Runtime，仅声明麦克风 entitlement；服务启动前检查自身签名和资源。更新重签保留加固标志与权限声明。
2. 两端优先使用内置服务；Node 启动及版本探测过滤可加载代码或削弱 TLS 的环境变量。保留企业 CA 配置。
3. Mac 使用进程持有的系统文件锁，避免并发普通实例；隔离测试实例不注册全局快捷键。Windows 继续使用已有互斥锁。
4. 已识别终端的自动粘贴压平换行、删除控制字符。普通编辑器不变。
5. Mac 历史及保留录音使用 AES-GCM 和独立钥匙串密钥；Windows 历史使用当前用户 DPAPI。迁移成功后才替换旧数据；失败保留原数据并提示，不回退为明文。
6. 服务历史默认只存文字摘要；旧明文在启动前原子迁移，失败则不启动。显式 `logRaw: true` 仍保存明文。

## CI 与未验证项目

PR #17 的 GitHub 检查注释明确说明：任务因付款失败或消费上限未启动。它们不能算作代码测试失败，也不能算作通过。没有修改 CI、伪造状态或绕过合并规则。

- Windows 原生 DPAPI、Windows 实机界面仍需 Windows runner 或真机验证。
- 本轮未验证新安装包、软件内更新、实际麦克风授权及已安装 App 的钥匙串交互。未运行本轮三平台真实识别模型检查；识别引擎未改动。
- Mac 编译与单元测试不等同于完整中英文 UI 操作验证。
- 加固检查不验证独立发布者身份，不能防止整体替换并重新签名。没有增加 Apple 公证或 Windows 发布签名。
- 更新包没有独立可信签名。`runtime.json` 所指本地服务也没有独立身份认证；同用户恶意进程可能冒充服务。这些仍需独立方案确认，本轮没有实现挑战应答协议。
- 本地加密不能防止已控制当前用户会话的攻击者。短文本摘要可能被猜测。词典和活动计数不在本轮历史加密范围内；录音和请求期间仍有临时明文 WAV。终端过滤不能识别所有内嵌终端，也不审查命令内容。
