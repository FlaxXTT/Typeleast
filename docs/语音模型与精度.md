# 语音模型、精度与本地导入

主下载入口按模型系列显示 Qwen3-ASR-0.6B 和 Qwen3-ASR-1.7B。格式必须在对应平台通过真实加载和识别测试后才开放。新用户自行选择，不预选、不自动下载；旧安装保留可用的模型选择。

ONNX Runtime 是推理后端。INT8、FP16、FP32 是权重或计算格式，不是同一种东西。一个包可能混合多种格式，不能只根据文件名声称全模型都是一种精度。更大模型、更多位数不保证每条语音都更准确；需要同一语音对比识别结果、耗时和内存。

## 来源与更新核对

2026-10-26 核对公开说明：

| 系列 | 当前路线与边界 |
| --- | --- |
| SenseVoice Small | 轻量、五语种；没有确认可直接替换本项目当前包且更准确的新权重。仓库或运行格式更新不是权重升级。 |
| FireRedASR2 CTC | 中文、方言、CTC；项目已经使用 v2 CTC。AED 和 LLM 是不同路线，不能作为同一个包直接升级。 |
| Fun-ASR-Nano | 中英日、口音；另有 MLT 多语种分支和 Transformers 原生格式，不能据此声称所有场景都更准。 |
| Qwen3-ASR | 0.6B／1.7B，多语种与中英混说；本项目只接入现有 sherpa 适配器兼容的 ONNX，不安装 Python 或 Transformers。 |

来源：[SenseVoice](https://github.com/QwenAudio/SenseVoice)、[FireRed](https://k2-fsa.github.io/sherpa/onnx/FireRedAsr/pretrained.html)、[Fun-ASR](https://github.com/QwenAudio/Fun-ASR)、[Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR)。

1.7B FP16 的候选来自 [luigi000 的独立转换包](https://huggingface.co/luigi000/qwen3-asr-1.7b-onnx-fp16)，不是 Qwen 或 sherpa 的官方转换发行。图包含 FP32 前端和 FP16 编码器／解码器，并使用外部权重。发布方主要描述 CUDA 用法，本项目必须单独验证当前 CPU 后端。发布方的“无精度损失”等描述不作为本产品承诺。

本轮在 Mac、sherpa-onnx-node 1.13.8、CPU、2 线程下，两条固定公开样例的观察如下。识别按最多 8 秒截取，不调用外部整理模型：

| 格式 | 加载 | 中文 5.592 秒 | 英文 7.152 秒 | 进程峰值内存 |
| --- | --- | --- | --- | --- |
| 0.6B INT8 | 1.086 秒 | 0.425 秒 | 0.544 秒 | 约 2.39 GiB |
| 1.7B FP16 | 5.024 秒 | 1.304 秒 | 1.696 秒 | 约 12.53 GiB |

两者中文分别写出“早上9點至下午5點”和“早上九點至下午五點”，英文样例结果相同。这说明 1.7B FP16 能在此环境运行，不能证明它在所有场景更准确。下载包约 4.73 GB，加载峰值明显高于文件大小。时间与内存不是最低配置保证，其他平台、语音长度和系统状态可能不同。当前 20 秒语音分段配合 512 token 上下文和 384 token 输出上限，不照抄转换包面向更长语音的 4096 上下文配置，以免无谓增加内存。

### 合成语音观察

使用系统 Tingting 离线生成虚构口述，不播放、不使用麦克风、不调用外部整理模型：

| 合成文本 | 0.6B INT8 | 1.7B FP16 |
| --- | --- | --- |
| 我想买一台 ROG 电脑，主要用来剪视频，不是打游戏。 | 缩写位置输出 Walk，其余用途和否定保留 | 缩写位置输出“沃克”，其余用途和否定保留 |
| 我想买一台华硕玩家国度的电脑，拼法是 R O G，主要用来剪视频，不是打游戏。 | 保留“华硕玩家国度”和 R O G | 保留“华硕玩家国度”和 ROG |
| 至少三四个人，再给五六天，预算不超过三万元。 | 保留原数值、范围及否定 | 保留原数值、范围及否定 |

合成器对缩写的发音可能有歧义，不能把脚本文字直接当作音频的正确发音证据，也不能将这组结果推广到真实用户。明确语境和拼写为后续整理提供了可用证据。数字的阿拉伯化由本次整理链路处理，不能把这三条 ASR 原文写成最终模型整理实测。

复现工具为开发者脚本 `service/scripts/compare-qwen-formats.mjs`：显式传入 `--baseline-dir`、`--candidate-dir`、`--samples-dir`；可用 `--sample-file`、`--language zh` 比较一条完整公开或合成语音。脚本不读取应用偏好或凭据。

### 云端测试资源边界

首次 CI 中，1.7B FP16 在 Windows 和 Linux 均通过实际加载、自动语言及中英粤日韩短样例测试。Mac 的标准 ARM runner 在此模型阶段等待 10 分钟后超时，没有识别结果，不能记为通过。

[GitHub runner 规格](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)列出标准 Mac ARM runner 为 7 GB 内存。本机所见约 12.5 GiB 峰值超过这一配置，因此资源不足是主要嫌疑；超时日志本身没有证明 OOM。Mac 本机实测与 Mac 云端测试须分开报告，不能用一处通过隐去另一处失败。

本轮按维护者选择：Mac 1.7B FP16 以已完成的隔离本机测试验收。CI 仅在显式传入 `--allow-resource-skip`、平台为 Mac、内存小于 14 GiB 时跳过这一模型，输出结构化 skipped 记录并写入 Actions 摘要；不下载该模型，也不把它记作通过。14 GiB 是测试预算，不是产品最低配置保证。Windows、Linux 不使用这个跳过条件；没有显式参数时，本地脚本仍尝试全部模型。

## 其他模型

“其他模型”默认收起。用户自行下载文件后，选择本地目录、名称、模型家族及相对文件映射。兼容范围为现有 SenseVoice、FireRed CTC、Fun-ASR-Nano、Qwen3-ASR 适配器支持的 ONNX 结构。文件后缀相同不保证兼容。

服务仅检查内置模型目录或用户指定目录，不扫描整台电脑。对已下载的旧模型提供“一键配置”，点击后才保存登记；不移动或删除原文件。移除登记不删除权重，当前正在使用的登记须先切换后再移除。

导入说明只接受数据，不允许脚本、动态库、命令或任意原生配置。检查图中外部权重引用、目录边界、符号链接及算子域。未知模型由独立进程加载，环境不带整理 API Key、服务鉴权令牌、用户历史或光标上下文。模型加载成功不证明安全；独立进程也不是操作系统安全沙箱。用户只应导入来源可信的模型。

新增本机接口沿用 `/api/voice-polish`、Host 检查和令牌鉴权：

- `POST /models/local/inspect`：检查 `{name, family, directory, files}`，不执行模型，返回名称、大小和图的数据类型。
- `POST /models/local/register`：同一描述，返回操作 ID；异步独立进程试加载成功后才登记，不自动切换。
- `POST /models/local/remove`：`{modelId}`，只移除登记。
- `POST /models/register-known`：`{modelId}`，检查已有内置文件并登记，不下载。
- `GET /models`：保留旧字段，增加系列、精度、分类、登记状态和适配模板。保存具体格式的稳定 ID。

## 后续：Mac 官方 MLX 后端扩展

此项是后续方案，本轮没有实现或启用。

现有插件是词库／风格数据，不能执行 MLX 代码。MLX 需要新的“官方语音后端扩展”类别及版本化接口，不放宽现有数据插件权限。Mac 用户可下载官方签名的后端组件及兼容权重，再自行选择经验证的 FP16／FP32；不自动安装或替换 ONNX。

后端边界包括：能力查询、模型检查与加载、识别、取消、释放，以及结构化错误。通过独立进程调用，核心不导入第三方插件代码。后端只接收本次音频、识别语言和明确允许的术语提示，不接收整理 Key、历史或光标上下文。模型管理与整理流程仍由核心负责，移除扩展后 ONNX 路线继续可用。

实施前须验证 MLX 发行许可、Mac／Apple 芯片支持范围、FP16／FP32 的实际权重与运算格式、内存、长音频和取消行为。组件签名、更新、卸载、回滚和兼容性单独设计；不承诺 FP32 一定更准或更快，不允许市场中的任意数据插件安装可执行后端。
