# ASR 术语与常用英语词对照

## 判断边界

本机 ASR 给出文字，整理模型只负责修正有证据支持的写法。一个普通英语词与产品名同形、同音，**读音相近并不能证明说话人指的是产品**。词库关闭时，标准整理提示词不再列举任何技术品牌。

分析时参考 [CMU Pronouncing Dictionary](https://github.com/cmusphinx/cmudict) 的美式英语读音和 [Ghent University SUBTLEX-US](https://www.ugent.be/plone_portal/pp/experimentele-psychologie/en/research/documents/subtlexus/overview.htm) 的常用词频。读音和词频只能帮助找出易混淆的词，不能单独决定一句话的意思；资料只用于开发分析，不随安装包分发。中文近音仍使用项目已有的 `pinyin-pro`，不能据此推断说话人的口音。

| 类别 | 原话样例 | 可能的专名 | 处理依据 |
|---|---|---|---|
| 普通词／产品名 | `cloud storage` | Claude | `storage` 表示普通云服务；不提供 Claude 候选 |
| 普通词／产品名 | `cloud 模型` | Claude | 启用技术插件且同一句有“模型”等语境词时，仅提供候选，仍由模型按句意判断 |
| 普通词／语言名 | `go ahead`、`go 语言` | Go | 前者保留动词；后者在插件启用时可提示语言名 |
| 普通词／框架名 | `react to the news`、`react 组件` | React | 前者保留动词；后者可提示框架名 |
| 普通词／语言名 | `metal will rust`、`rust 编译` | Rust | 前者保留普通名词／动词；后者可提示语言名 |
| 普通词／工具名 | `move the cursor`、`Cursor 编辑器` | Cursor | 光标与编辑器依语境区分 |
| 人名／缩写 | `杰森来开会`、`杰森格式` | JSON | 人名不改；“格式”等近邻词可触发 JSON 候选 |
| 音译／语言名 | `派森来开会`、`派森脚本` | Python | 人名不猜；“脚本”等近邻词可触发 Python 候选 |
| 缩写／普通语句 | `戴套`、`DTO 接口对象` | DTO | 只有明确的接口或数据传输语境才提示 DTO |

## 实现规则

1. 第 1 版词库仍只存术语写法。第 2 版词库增加有界的 `heard`、`term`、`cues` 文字字段；不接受代码、正则或整份系统提示词。
2. 别名只在**当前口述**出现，且同一句附近有语境词时才进入本次模型请求。光标附近文字不能独自触发别名。服务只传命中的候选，不传整份词库或所有语境词。
3. 用户自己的词典和「不发给模型」规则优先。后者继续只在本机处理。插件提示属于候选，不能改写任务规则，不能强制把普通词换成品牌。
4. 原话转写不调用整理模型，不按近音替换；启用新版词库时，只能对不歧义的完整词调整大小写。未启用词库时不做品牌大小写修改。
5. 词典建议仍需用户点击“加入”。常用英语词与品牌同形的模型猜测不自动生成建议，避免把一次误判变成长期纠错规则。

这些规则不能保证所有口音、姓名或领域术语都正确。真实效果要用获得授权的公开或合成语音按模型分别验证；本次的文字样例只检查候选筛选和输出边界。当前使用的 sherpa-onnx [热词偏置仅支持 transducer 模型](https://k2-fsa.github.io/sherpa/onnx/hotwords/)，不能直接套用到所有已提供的识别模型。
