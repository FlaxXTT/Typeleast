# TypeLeast 架构与交接说明

写给接手开发的人（或 AI agent）。先读这份，再读 `README.md`、`CHANGELOG.md`。提交规则以仓库维护者给出的「GitHub 提交规则」为准（要点见文末）。

## 1. 它是什么

按快捷键说话 → 本机识别（SenseVoice，通过 sherpa-onnx 运行）→ 用用户自己的 OpenAI 兼容 API Key 整理 → 粘贴到光标处。

- 三个部分：**本地服务** `service/`（Node ≥ 22），**Mac 客户端** `apps/macos/`（Swift + SwiftUI/AppKit，用 `swiftc` 直接编译，没有 Xcode 工程和第三方依赖），**Windows 客户端** `apps/windows/`（C# WPF，.NET 8）。
- 两个客户端都不做识别和整理，只负责录音、热键、粘贴、界面，所有智能都在本地服务里。
- API Key 只存在系统钥匙串 / 凭据管理器里，**每次请求通过请求头带给服务**，服务不落盘。

## 2. 目录

```

  bin/typeleast-service.mjs   入口
  lib/                        业务代码（见第 3 节）
  lib/prompts/                系统提示词：erduo-budget-typeless.js、promptify.js
  scripts/                    手动验收和模型下载脚本（不进 CI）
  test/*.test.js              node:test 单元测试（npm test）
apps/macos/
  Sources/*.swift             App 源码（见第 4 节）
  Tests/main.swift            自写测试框架，test.sh 编译部分源文件后运行
  build.sh                    编译 + 本机签名 + 安装到 ~/Applications 并启动（--no-install 只编译）
  make-signing-cert.sh        每台 Mac 一次：生成本机固定签名证书
  package.sh                  发布用：打包 .dmg/.zip（内置 Node.js），CI 调用
  Tools/                      截图渲染、演示录屏、宣传片工具（不进 App）
apps/windows/
  TypeLeast.Core/             不依赖 WPF 的逻辑（可测试）
  TypeLeast.Core.Tests/       控制台测试程序
  TypeLeast/                  WPF App（Ui/ 下是界面）
  package.ps1 + installer/    发布用：免安装 zip + Inno Setup 安装包

```

## 3. 本地服务：模块与耦合

调用方向（左边依赖右边）：

```
bin/typeleast-service.mjs → server.js
server.js  → config.js, paths.js, token.js, runtime.js, history.js, asr.js, service.js, http.js
http.js    → service.js 的实例（构造时注入）, token.js, wav.js, context.js, openai-compat.js
service.js → prompt.js, openai-compat.js → llm.js, parse-output.js, validate.js, tidy.js, context.js, wav.js, prompts/promptify.js
prompt.js  → prompts/erduo-budget-typeless.js, prompts/promptify.js
asr.js     → models.js, wav.js
```

| 文件 | 职责 | 关键导出 |
| --- | --- | --- |
| `server.js` | 组装：读配置、建状态目录、生成 token、加载词典和 promptify、监听 127.0.0.1 随机端口、写 `runtime.json`、父进程退出时自杀（`--parent-pid`） | `startService` |
| `http.js` | 路由、Bearer 鉴权、Host 校验、请求头解析 | `createHandler` |
| `service.js` | 核心类，整理流水线、词典、历史、promptify 设置 | `VoicePolishService` |
| `prompt.js` | 拼系统提示词：Erduo 原文 +「统一主语」+ 示例，或 promptify；再加词典 / 光标上下文附录。`PROMPT_VERSION` 改提示词时要改，有测试锁定 | `systemPromptFor`, `PROMPT_VERSION` |
| `prompts/erduo-budget-typeless.js` | Erduo 原文（第三方，来源见 THIRD-PARTY-NOTICES.md，**原文不改**）+ 我们加的第 5 条 `SUBJECT_CONSOLIDATION` | `erduoSystemPrompt` |
| `prompts/promptify.js` | 提示词模式默认提示词（CO-STAR + 角色）与长度上限 | `PROMPTIFY_PROMPT`, `promptifySystemPrompt` |
| `openai-compat.js` | 调用 `/chat/completions`；解析 `x-voice-llm` 路由头 | `completeOpenAI`, `parseRouteHeader` |
| `llm.js` | 超时、错误分类 | `ModelCallError`, `failureReason` |
| `parse-output.js` | 从模型回复里取正文 | `parsePolishOutput` |
| `validate.js` | 防编造 / 防跑题校验：新数字、日期、标识符、语言变化、覆盖率、长度。提示词模式放宽（只拦编造的阿拉伯数字、日期词、标识符，不查语言） | `validateOutput` |
| `tidy.js` | 不调模型的确定性清理（语气词、重复），也是所有退路的输出 | `tidy` |
| `context.js` | 光标上下文解析与脱敏，`redactSecrets` 发出前遮掉口述的 Key/密码 | `redactSecrets` |
| `asr.js` / `models.js` / `wav.js` | 识别、模型下载（逐文件 SHA-256）、WAV 校验 | `LocalRecognizer`, `downloadModels` |
| `history.js` / `runtime.js` / `token.js` / `paths.js` / `config.js` | 历史、运行信息、鉴权 token、目录、配置与 `STRENGTHS` | |

**整理流水线 `service.polish()`**：空文本→退出；`off`→只 `tidy`；没有可用路由（没 Key）→只 `tidy`；否则 `buildContext`（脱敏上下文）→ 提示词模式时 `refreshPromptify()`（文件被手动改过就重读）→ `systemPromptFor` → `redactSecrets(原话)` → `completeOpenAI` → `parsePolishOutput` → `tidy` → `validateOutput`，不通过或出错都退回 `tidy(原话)`，`fallback: true` 并记原因。提示词模式 `max_tokens ≥ 1600`、超时 ≥ 25 秒。

**HTTP 接口**（都要 `Authorization: Bearer <token>`，token 和端口在状态目录的 `runtime.json`）：
`GET /health` · `POST /dictate`（WAV → 识别 + 整理）· `POST /polish`（文本 → 整理）· `GET /history` · `POST /learn` · `GET|PUT /dictionary` · `POST /models/download` · `POST /test-llm` · `GET|PUT /prompts/promptify`

**请求头**：`x-voice-llm`（base64 JSON：baseURL、model、apiKey）、`x-voice-strength`（客户端只发 `off` / `prompt` / `promptify`；服务的 `STRENGTHS` 还保留旧档位 `conservative`、`maximal`）、`x-voice-language`、`x-voice-app`、`x-voice-context`（base64 JSON：光标前后文、选中、窗口标题）。

**状态目录**：Mac `~/Library/Application Support/TypeLeast/`，Windows `%APPDATA%\TypeLeast\`（模型在 `%LOCALAPPDATA%\TypeLeast\models`）。文件：`runtime.json`、`api-token`、`history.jsonl`、`dictionary.json`、`promptify.json`（`appendix` 追加、`override` 替换，可手动编辑，下次整理生效）、`models/`。

## 4. Mac 客户端：模块与耦合

- **中枢是 `AppDelegate`**（分在 `AppDelegate.swift`、`+Dictation.swift`、`+Update.swift` 三个文件），它实现 `AppActions`（界面调用）和 `MenuActionTarget`（菜单调用）两个协议，持有 `MenuController`、`Recorder`、`ServiceClient`、`ServiceManager`、录音条等。
- **界面是 SwiftUI**：`HubWindow`（主窗口）→ `HubPages`（首页 / 历史 / 词典）、`HubSettings`（设置；所有开关走 `ToggleRow` + `StateSwitchStyle`，开绿关灰）、`PromptifySettings`（提示词模式：默认锁定、追加、两次警告 + 6 位验证码才能改默认、恢复默认）。界面只通过 `AppModel.shared`（`ObservableObject`）读状态、通过 `model.actions?` 调 `AppDelegate`。
- **设置**：`Settings`（UserDefaults，键名带 `voice.` / `llm.` 前缀，bundle id 仍是历史遗留的 `com.dsh.voice`，**不要改**，改了会丢设置和权限）。`LLMSettings.swift` 里有服务商预设 `LLMPreset`、`KeychainStore`（服务名 `TypeLeast.llm-api-key`，账户名是预设 id；测试里必须设 `KeychainStore.stub`，否则会读真实钥匙串并弹窗）。
- **听写状态机** `AppDelegate+Dictation.swift`：`idle → recording → thinking → idle`；开始提示音是 `StartChime`（合成的 E6→B6 两声），结束是系统 Pop。
- **服务通信** `ServiceClient`（同步 HTTP，读 `runtime.json`），`ServiceManager` 负责找 Node.js（App 内置 > 系统）并启动服务。
- **插入**：`Inserter`（剪贴板 + 合成 ⌘V，事后恢复剪贴板，切了窗口就不粘贴）。`FieldContext` 读光标上下文（辅助功能 API），`EditLearner` 从用户改动里学词。
- **热键**：`HotKey`（Carbon 热键）+ `FnKey`（单按 Fn）。
- **更新** `Updater.swift` + `AppDelegate+Update.swift`：用本机 `gh` 的登录从私有仓库下载最新 Release 的 zip → 核对 SHA256SUMS.txt → 用本机证书「TypeLeast Local Signing」重签 → 比对签名要求与当前一致 → 退出后替换并重启。只在装了 gh 且有本机证书的 Mac 上可用。

## 5. Windows 客户端

`TypeLeast.Core`（可测试）：`ServiceClient`、`ServiceLocator`（找 Node）、`AppSettings`、`LocalHistory`、`LlmPresets`、`TapDetector`、`Models`（含 `PromptifySettings`、`PromptifyGuard`）。
`TypeLeast`（WPF）：`AppHost`（中枢，对应 Mac 的 AppDelegate）、`KeyboardHook`、`AudioRecorder`（NAudio）、`Paster`、`Tray`、`ServiceManager`、`Ui/`（`MainWindow`、`SettingsPage`、`PromptifyPanel`、`RecordingBar`、`Theme`）。
Windows 版的提示词模式界面**只在 CI 上编译和跑过单元测试，没在真机上点过**。

## 6. 构建与测试

```bash
cd service && npm ci && npm test            # 服务：160 项
apps/macos/test.sh                          # Mac：293 项（新加源文件要同时加进 test.sh 的编译列表才能被测试引用）
apps/macos/make-signing-cert.sh             # 每台 Mac 一次
apps/macos/build.sh                         # 编译、签名、安装、启动
```

Windows 只在 CI 上编译测试（`dotnet run --project TypeLeast.Core.Tests`、`dotnet build`）。
真实模型自检：App 支持 `TYPELEAST_SELFCHECK`、`TYPELEAST_LLMCHECK_URL/_MODEL/_KEY=@keychain/_WAV/_STRENGTH` 环境变量；配合 `open -n -g --env TYPELEAST_HOME=<临时目录> ...` 启动编译到临时目录的 App，不影响已安装版本。

## 8. 已知限制 / 待办

- Windows 提示词模式界面未经真机验证。
- 软件内更新只覆盖维护者自己的 Mac（私有仓库 + 本机证书）。发布包仍是 ad-hoc 签名，其他用户每次更新都要重新授权；要解决需 Developer ID 或公开的发布仓库。
- Windows 版没有软件内更新。
- 历史上 6f674f2 的提交者邮箱、v1.3.0 标签的时区不符合现行规则，按维护者要求保留历史、不改写。

## 9. 改代码时的约束

- 提示词：Erduo 原文不改，新增策略写成独立常量拼接；改了提示词就改 `PROMPT_VERSION` 和锁定它的测试。
- 改了服务接口：同时改 `ServiceClient.swift`、`TypeLeast.Core/ServiceClient.cs` 和两边测试。
- Mac 新增设置开关一律用 `ToggleRow`。
- 测试里不得读真实钥匙串、不得用真实听写内容、不得写真实路径或用户名（用 `/Users/someone`、`sk-test-…` 这类假值）。
- 提交、PR、发布流程见维护者的「GitHub 提交规则」：分支 → PR → CI 全过 → 快进合并；不强推；每次发布写 CHANGELOG 和 `.github/release-notes.md`。


## 10. 界面语言与隐私检查（1.4.0）

- Mac `L10n.swift` 和 Windows Core `L10n.cs` 集中管理中英文界面文字；中文原文为查找键，动态内容通过参数传入，不对用户文本做翻译查找。
- 独立界面语言设置：`system` / `zh-Hans` / `en`，重启生效。中文系统默认简体中文，其余默认英语；听写语言独立。
- 服务通过现有 `x-voice-language` 接收逐次听写语言，校验后传到识别器；识别任务串行处理，语言改变时重建单个识别器，避免共享配置串扰。
- 模型请求禁止自动重定向。中文显式凭据、词典与光标上下文经过脱敏；错误请求不回显 JSON 片段，桌面诊断不保留原始异常文本。
- `node service/scripts/check-localization.mjs` 检查两端翻译覆盖和格式参数。检查结果及限制见 `docs/检查与验证-1.4.0.md`。
