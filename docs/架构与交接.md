# TypeLeast 架构与交接说明

写给接手开发的人（或 AI agent）。先读这份，再读 `README.md`、`CHANGELOG.md`。提交规则以仓库维护者给出的「GitHub 提交规则」为准（要点见文末）。

> 未发布重构以 [统一听写与需求助手](统一听写与需求助手.md) 为准：已移除当前档位选择，增加任务类型、十分钟录音、共享整理预算与独立需求助手。下方带版本号的小节仍用于追溯历史设计。

## 1. 它是什么

按快捷键说话 → 本机识别（默认 SenseVoice，可选模型通过同一 sherpa-onnx 引擎运行）→ 用用户自己的 OpenAI 兼容 API Key 整理 → 粘贴到光标处。

- 三个部分：**本地服务** `service/`（Node ≥ 22），**Mac 客户端** `apps/macos/`（Swift + SwiftUI/AppKit，用 `swiftc` 直接编译，没有 Xcode 工程和第三方依赖），**Windows 客户端** `apps/windows/`（C# WPF，.NET 8）。
- 两个客户端都不做识别和整理，只负责录音、热键、粘贴、界面，所有智能都在本地服务里。
- API Key 只存在系统钥匙串 / 凭据管理器里，**每次请求通过请求头带给服务**，服务不落盘。

## 3. 本地服务：模块与耦合

### 客户端控制器拆分（1.18.0）

两端沿用 `UpdateController` 和 `DictionaryController`，继续拆出 `BetaController` 与 `DictationController`。本地服务接口、提示词、词典建议算法和存储格式不变。

- `BetaController` 管理会话 ID、最初的目标应用/输入框、每轮补充、面板显示与取消。普通翻译不会消耗等待中的 Beta 会话。Mac 通过显示/隐藏/取消回调连接面板与服务；Windows 由会话控制器管理面板。
- `DictationController` 管理录音、录音条、识别整理请求、取消、重试与结果插入；调用 Beta 控制器和词典控制器。Mac 通过 `Host` 接收资源与界面回调，Windows 通过 `IDictationHost` 接收资源与应用回调，不引用 `AppHost` 实现类。
- `AppDelegate` / `AppHost` 保留应用启动、快捷键接线、窗口、服务状态和设置入口。已有 UI 入口转发给控制器，不再各自维护第二份听写状态。
- Mac 测试编译全部生产模块但不运行应用入口；新增 Beta 测试不实例化日常应用模型。Windows 渲染任务在独立状态目录、假凭据下检查控制器组合，不启动服务或麦克风。

调用方向（左边依赖右边）：

```
bin/typeleast-service.mjs → server.js
server.js  → config.js, paths.js, token.js, runtime.js, history.js, speech-models.js, service.js, http.js
http.js    → service.js 的实例（构造时注入）, token.js, wav.js, context.js, openai-compat.js
service.js → prompt.js, openai-compat.js → llm.js, parse-output.js, validate.js, tidy.js, context.js, wav.js, prompts/prompt-beta.js
prompt.js  → prompts/cleanup.js, prompts/concise.js
asr.js     → models.js, wav.js
speech-models.js → asr.js, models.js
models.js  → asr-catalog.json
```

### 可选识别模型（v1.5.0 开发分支）

`speech-models.js` 管理下载、校验、加载、切换与服务端选择持久化。`speech-model.json` 只保存模型 ID。下载与正在使用的识别器分离，校验、加载和保存全部成功后才替换；失败保留当前模型。识别与切换共用串行队列；切换等待整理中的请求完成。候选各用独立目录，共享 `vad/silero_vad.onnx`，原 SenseVoice 目录不变。

`GET /api/voice-polish/models` 返回清单、安装状态、操作状态与当前模型。`POST /models/download` 接收 `modelId`、`activate` 和 `endpoint`；缺少 ID 的旧请求默认 SenseVoice。`PUT /models/active` 启用已有模型；`POST /models/download/cancel` 取消下载或等待中的切换。后三条同样位于 `/api/voice-polish` 下，沿用鉴权与请求体大小限制。`/health` 保留旧字段并增加模型 ID、名称、语言能力和操作状态。

SenseVoice 语言变更用 `setConfig`；Fun-ASR-Nano 需要重新加载语言配置；Qwen3-ASR 使用逐请求的 `stream.setOption("language", ...)`；FireRed CTC 自动检测。两端用 `node --expose-gc` 启动服务，模型替换后释放旧引用并回收原生内存。直接运行服务也应使用该参数，或使用 `npm start`。

真实模型验证命令（明确指定缓存和隔离状态目录，不读取应用历史）：

```sh
cd service
node scripts/check-asr-models.mjs --download --models-dir /path/to/model-cache --state-dir /path/to/isolated-state
```

该脚本使用固定公开短样例，依次运行各模型并记录加载、识别和内存数据。它不调用整理模型，不表示准确率排名。完整状态见 `docs/v1.5.0-验证记录.md`。

**整理流水线 `service.polish()`**：空文本退出；旧 `off` 按自然整理处理。自然整理和 AI 整理依次准备上下文 → 生成 → 解析 → 数字与标点清理 → 程序校验 → 按风险进行一次语义审查 → 交付同一候选。自然整理默认 1800 tokens，按长度可增至 4096，单次 18 秒、温度 0.8；AI 整理 1600 tokens、25 秒、温度 1.0。两档均非流式。整个整理过程共享 60 秒总预算和一次技术重试。失败时 `text` 为空，`clarification.kind=quality` 的候选仅供非模态窗口编辑；可继续整理、直接使用用户修改或取消，不自动插入原文或未通过的草稿。

**翻译走 `polishTranslate()`**：请求带 `translateTo`（`x-voice-translate` 头，或 `/polish` 请求体）时，不管当前整理档位，先在原语言自然整理并校验，再把整理稿交给第二次模型调用翻译。译文允许自然调整句式；校验用 `validateOutput(strength:"translate")`，按数值比对数字（`translationInventedNumbers`）。第一步的整理稿无法解析或没通过校验时，改用 `directTranslatePrompt` 一次调用直接翻译原话（按原话校验，结果 `detail` 为 `direct-after:<原因>`），这次也失败才回退 `tidy(原话)`；第二步失败时保留已校验的原语言整理稿。无 Key 时回退 `tidy(原话)`。结果带 `translated`；翻译通常比一次整理更慢，用量更高。

**词汇**：个人词典与启用的词库插件经 `personalization-policy.js` 按本次口述筛选（`dictionary-relevance.js` 写法或读音匹配，`term-hints.js` 语境读音提示），只把相关条目写进附录。当前口述的全称、拼写和改口优先；自动条目只给写法，明确替换需逐条确认。`POST /learned-word` 由 `edit-correction.js` 判断用户刚改的词。

**语言变体**：`x-voice-variants`（或请求体 `variants`）在 `recordAndReturn()` 里最后一步转换中文，所以历史和返回的文字一致；英式拼写是加在普通整理或翻译第二步系统提示词末尾的一句。

**整理档位**：`prompt`（自然整理）、`concise`（AI 整理）、`promptbeta`。旧值 `off` 迁移为 `prompt`；旧值 `promptbrief`、`promptify` 迁移为 `concise`。`utterance-rules.js` 约束本次改口、名称、否定和条件。自然整理与 AI 整理共用风险审查和挂起交付机制；Beta 使用独立的多轮与审查流程。

**更新摘要（1.18.0）**：Mac 的 latest 接口和 Windows 的 releases 列表在现有请求中读取 `body`。发布说明用 `<!-- typeleast-update:zh -->` / `<!-- typeleast-update:en -->` 开始、`<!-- /typeleast-update -->` 结束标记；`ReleaseSummary` 按界面语言选择，缺少目标语言时回退另一种语言，旧说明回退为前几条正文。最多 4 条、每条 140 字符，以纯文本显示，删除控制字符和标记，不执行 HTML、不请求正文中的链接。没有摘要仍可更新。更新确认／检查提示和下载进度中显示摘要；旧客户端升级到本版前无法使用这项新 UI。

**提示词 Beta（`promptbeta`）走 `polishBeta()`**：首次和每次回答都分析最初口述及全部已接受回答；返回 `{text:"", beta:{sessionId, questions, confirmed, round, ready, notice?}}`。客户端只要收到有效 `sessionId` 就继续等待，不能以 questions 为空判断结束；`ready` 仅表示目前没有待问问题。问题不超过每轮 4 个，摘要不超过 6 条，不对缺口做合理假设。静音、空回答不推进或生成；失败轮的补充不会悄悄记作已接受，`notice` 提示重说，之前的信息保留。会话只在内存，15 分钟空闲过期、最多 20 个，原话和回答总计上限 24000 字符，超限明确拒绝本轮而不截断；同一会话并发请求返回 409。取消会中止模型调用，迟到结果不能复活会话。

用户明确调用 `POST /prompts/beta/finish` 后才起草 → 独立原意审查 → 有问题才最小修补并再次审查 → 事实校验。仍有问题不插入，保留会话供补充或重试；成功才写最终历史并结束会话。每轮分析为一次调用，最终生成 2–4 次调用；每次超时至少 60 秒，客户端 Beta 超时至少 300 秒。中间录音不保留为可重试文件。问题、摘要和规格不作为用户确认的事实来源，最终内容只能来自用户口述和补充。

**HTTP 接口**（都要 `Authorization: Bearer <token>`，token 和端口在状态目录的 `runtime.json`）：
`GET /health` · `POST /dictate`（元数据 + WAV → 识别 + 整理）· `POST /polish`（文本 → 整理）· `POST /models/download` · `POST /test-llm` · `POST /learned-word`（用户改词后判断要加入词典的词）· `POST /prompts/beta/finish` · `POST /prompts/beta/cancel`

**请求头**：保留 `x-voice-llm`、`x-voice-strength`、`x-voice-language`、`x-voice-app`、`x-voice-context`、`x-voice-beta-session`、`x-voice-translate` 和 `x-voice-variants`。`x-voice-dictionary-bytes` 作为兼容的 JSON 元数据前缀长度继续读取；其中包括词典条目，以及解释段、确认信息、表达示例与关闭个性化等元数据。Key 只随当前请求进入本机服务，模型请求前脱敏口述与上下文。

**状态目录**：Mac `~/Library/Application Support/TypeLeast/`，Windows `%APPDATA%\TypeLeast\`（模型在 `%LOCALAPPDATA%\TypeLeast\models`）。文件：`runtime.json`、`api-token`、`models/`。

## 4. Mac 客户端：模块与耦合

- **中枢是 `AppDelegate`**（分在 `AppDelegate.swift`、`+Dictation.swift`、`+Update.swift` 三个文件），它实现 `AppActions`（界面调用）和 `MenuActionTarget`（菜单调用）两个协议，持有 `MenuController`、`Recorder`、`ServiceClient`、`ServiceManager`、录音条等。
- **界面是 SwiftUI**：`HubWindow`（主窗口）→ `HubPages`（首页 / 历史 / 个人偏好）、`HubSettings`（设置；所有开关走 `ToggleRow` + `StateSwitchStyle`，开绿关灰）；整理档位在 `HubWindow` 左侧栏（`SidebarModes`），`Guide.swift` 是首页「设置在哪」卡片、引导最后一步和模型下载失败时的镜像提示。界面只通过 `AppModel.shared`（`ObservableObject`）读状态、通过 `model.actions?` 调 `AppDelegate`。
- **设置**：`Settings`（UserDefaults，键名带 `voice.` / `llm.` 前缀，bundle id 仍是历史遗留的 `com.dsh.voice`，**不要改**，改了会丢设置和权限）。`LLMSettings.swift` 里有服务商预设 `LLMPreset`、`KeychainStore`（服务名 `TypeLeast.llm-api-key`，账户名是预设 id；测试里必须设 `KeychainStore.stub`，否则会读真实钥匙串并弹窗）。
- **听写状态机** `AppDelegate+Dictation.swift`：`idle → recording → thinking → idle`；开始提示音是 `StartChime`（合成的 E6→B6 两声），结束是系统 Pop。
- **提示词 Beta**：首轮固定依次确认后续 AI 联网许可、背景资料清单、本地允许与禁止范围、重复或创新工作。只写入本轮需求，不执行检索或读取文件。`BetaPanel`（右上角不抢焦点的浮窗）展示每轮问题和当前理解，`betaPending` 保留最初的 App、输入框、模型路由、听写语言和写法设置。下一次听写继续补充，明确生成后才尝试贴回原输入框；离开未完成的 Beta 前要求确认，取消单次补充录音仍保留对话。
- **菜单栏** `MainMenu`：应用自己的主菜单（TypeLeast / 编辑 / 窗口）。没有它时切到主窗口，左上角仍显示上一个应用的菜单，输入框的 ⌘C / ⌘V 也不工作（AppKit 通过主菜单分发这些快捷键）。状态栏图标的菜单是另一个：`MenuController`。
- **翻译与活动**：翻译快捷键（槽位 `translate`，默认 ⇧⌥Space，不能是 Fn）开始的录音带 `pendingTranslate`，录音条显示「→EN」，不会被当成提示词 Beta 的回答。`ActivityLog`（UserDefaults `voice.activity.v1`）按天只记次数和字数，首次启动从现有历史补数据，「删除全部历史」一并清空；首页 `ActivityCard` 画热力图。
- **服务通信** `ServiceClient`（同步 HTTP，读 `runtime.json`），`ServiceManager` 负责找 Node.js（App 内置 > 系统）并启动服务。
- **插入**：`Inserter`（剪贴板 + 合成 ⌘V，事后恢复剪贴板，切了窗口就不粘贴）。`FieldContext` 读光标上下文（辅助功能 API），`EditLearner` 读回输入框，由服务的 `/learned-word` 判断从用户改动里学哪个词。
- **热键**：`HotKey`（Carbon 热键）+ `FnKey`（单按 Fn）。
- **更新** `Updater.swift` + `AppDelegate+Update.swift`：先匿名从公开发布页下载（`api.github.com/.../releases/latest`、`github.com/.../releases/download/...`），失败时用本机 `gh` 登录兜底 → 核对 SHA256SUMS.txt → 用本机证书「TypeLeast Local Signing」重签（没有就自动生成，等同 make-signing-cert.sh）→ 比对签名要求与当前一致 → `KeychainHandoff.transfer()` 以 `--receive-keychain-handoff` 启动新版本自己的可执行文件，按代码哈希（签名后取得的 cdhash）核对这个进程，再删除自己的条目并经标准输入交给它，新版本以自己的身份重建（不落盘；失败则原样放回，新版本询问一次）→ 退出后替换并重启。1.17.2 及以前写的 `keychain-handoff.json` 仍在启动最早期（`main.swift`，早于历史读取）由 `restoreIfPresent()` 恢复一次；有条目重建失败时保留该文件、下次启动重试，期间不会生成新的历史密钥。原因：本机证书没有 Apple 团队 ID，钥匙串按代码哈希授权，每个新构建读取旧条目都要输密码。Intel（x86_64）从 1.17.1 起停止发布，更新器提示停更；Rosetta 下的 Intel 版升级到 Apple 芯片版。

## 安全边界与历史存储（未发布）

- `SelfIntegrity` 在 Mac 服务启动前检查签名和密封资源；构建开启 Hardened Runtime，更新重签保留标志和权限声明。该检查不证明发布者身份，不防止攻击者替换整个 App 并重新签名。
- `InstanceLock` 使用系统文件锁；进程退出时自动释放。隔离测试实例不注册全局快捷键。
- 两端 `ServiceLocator` 优先内置服务，并为 Node 启动和版本探测过滤环境变量；保留企业 CA 的 `NODE_EXTRA_CA_CERTS`。开发覆盖仍可用于没有内置服务的开发环境。
- `HistorySeal` 使用 AES-GCM，独立密钥由钥匙串保存；旧偏好历史与应用临时录音迁移后删除原明文。失败时保留原数据、显示错误，不写入新的明文历史。录音采集与请求期间仍有临时明文 WAV。
- Windows `LocalHistory` 通过可替换的 `IHistoryProtection` 调用当前用户 DPAPI；原生实现仅在 Windows 运行，其他系统的单元测试使用替身。旧 JSON 原子替换为加密数据，损坏或无法解密的文件不会被后续保存覆盖。
- 服务不保存听写正文；历史只在两端 App 中加密保存。旧版服务 `history.jsonl`、`dictionary.json` 启动时清理。个人词汇在两端 App 中加密保存，见个人偏好文档。
- `TerminalGuard` 仅对已知终端过滤换行和控制字符，减少意外执行；不识别所有 IDE 内嵌终端，也不审查命令内容。
- 本地服务身份：App 每次自己启动服务，经 stdin 传入 32 字节随机密钥（`--auth-stdin`），不复用已在监听的服务；对每个新端口先发随机挑战，`/health` 用 HMAC-SHA256 回答，验证通过后才发送带 API Key 的请求，防止伪造 `runtime.json` 的进程截获 Key。
- 发布版（package.sh 设 `TYPELEAST_RELEASE=1`）编译掉自检和演示入口（`TYPELEAST_SELFCHECK`、`TYPELEAST_LLMCHECK_*`、`TYPELEAST_DEMO_WAV`）；开发版里 `@keychain` 只发往当前预设已保存的地址。
- 尚未处理：更新包的独立可信签名（维护者决定暂不加）。

测试与验证结果见 [安全加固验证记录](安全加固验证记录.md)。


### v1.22.1：AI 整理与名称确认

`concise` 标识保持兼容，两端显示为 AI 整理并排在首位。客户端以独立迁移标记将既有用户切换一次，随后保留用户选择；新用户默认 AI 整理。

词条保留 `source` 与原始 `heardAs` 数据。发送和本机替换使用 `requestEntry` / `RequestValue`：自动来源只提供词汇写法，手动来源才提供明确替换。用户手动编辑后标记为 manual。不把未编辑输出当作认可。

名称确认与 Beta 分开。服务可返回 `clarification: {question,evidence,target?}`；证据必须逐字出现在本次口述。新版客户端通过 `x-voice-clarification: 1` 或 `/polish` 的 `supportsClarification: true` 选择此行为。待确认响应 `text` 为空、不生成建议、不计为整理成功。旧客户端得到原文回退。

确认面板为非模态，可移动、编辑、继续口述、保留原文或取消。仅展示本次原话证据，不展示未经核对的模型候选。补充口述将前文作为 JSON 前缀中的 `{clarificationSource: text}` 发至原鉴权接口；服务将其与新识别合并后处理。元数据中的 `clarificationEvidence` 限定待确认片段；只有短而明确的名称或字母拼写回答、且片段在前文唯一时，才生成仅本次有效的替换依据，不写入词典。此前口述最多 32000 个字符，重复元数据拒绝。服务不新建长期会话、文件或凭据存储。

客户端保留初始目标及上下文边界。补充不会读取后来切换窗口的内容；结果仍经过原有目标窗口核验。确认以前不记录成功历史、不粘贴、不学习名称。保留原文表示明确使用原识别文本，包括翻译待确认时的源文本；编辑后重新整理，翻译仍走两步。

测试共享客户端契约升级为 `tests/conformance/client-v2.json`；v1 保留供旧实现参考。测试、报告和示例均不进入安装包。未修改 Beta 多轮协议、ASR 模型、插件权限或更新器。
