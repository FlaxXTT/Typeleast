# TypeLeast 架构与交接说明

写给接手开发的人（或 AI agent）。先读这份，再读 `README.md`、`CHANGELOG.md`。提交规则以仓库维护者给出的「GitHub 提交规则」为准（要点见文末）。

## 1. 它是什么

按快捷键说话 → 本机识别（默认 SenseVoice，可选模型通过同一 sherpa-onnx 引擎运行）→ 用用户自己的 OpenAI 兼容 API Key 整理 → 粘贴到光标处。

- 三个部分：**本地服务** `service/`（Node ≥ 22），**Mac 客户端** `apps/macos/`（Swift + SwiftUI/AppKit，用 `swiftc` 直接编译，没有 Xcode 工程和第三方依赖），**Windows 客户端** `apps/windows/`（C# WPF，.NET 8）。
- 两个客户端都不做识别和整理，只负责录音、热键、粘贴、界面，所有智能都在本地服务里。
- API Key 只存在系统钥匙串 / 凭据管理器里，**每次请求通过请求头带给服务**，服务不落盘。

## 3. 本地服务：模块与耦合

调用方向（左边依赖右边）：

```
bin/typeleast-service.mjs → server.js
server.js  → config.js, paths.js, token.js, runtime.js, history.js, speech-models.js, service.js, http.js
http.js    → service.js 的实例（构造时注入）, token.js, wav.js, context.js, openai-compat.js
service.js → prompt.js, openai-compat.js → llm.js, parse-output.js, validate.js, tidy.js, context.js, wav.js, prompts/promptify.js, prompts/prompt-beta.js
prompt.js  → prompts/cleanup.js, prompts/promptify.js
asr.js     → models.js, wav.js
speech-models.js → asr.js, models.js
models.js  → asr-catalog.json
```

### 可选识别模型（v1.5.0 开发分支）

`speech-models.js` 管理下载、校验、加载、切换与服务端选择持久化。`speech-model.json` 只保存模型 ID。下载与正在使用的识别器分离，校验、加载和保存全部成功后才替换；失败保留当前模型。识别与切换共用串行队列；切换等待整理中的请求完成。候选各用独立目录，共享 `vad/silero_vad.onnx`，原 SenseVoice 目录不变。

`GET /api/voice-polish/models` 返回清单、安装状态、操作状态与当前模型。`POST /models/download` 接收 `modelId`、`activate` 和 `endpoint`；缺少 ID 的旧请求默认 SenseVoice。`PUT /models/active` 启用已有模型；`POST /models/download/cancel` 取消下载或等待中的切换。后三条同样位于 `/api/voice-polish` 下，沿用鉴权与请求体大小限制。`/health` 保留旧字段并增加模型 ID、名称、语言能力和操作状态。

SenseVoice 语言变更用 `setConfig`；Fun-ASR-Nano 需要重新加载语言配置；Qwen3-ASR 使用逐请求的 `stream.setOption("language", ...)`；FireRed CTC 自动检测。两端用 `node --expose-gc` 启动服务，模型替换后释放旧引用并回收原生内存。直接运行服务也应使用该参数，或使用 `npm start`。

真实模型验证命令（明确指定缓存和隔离状态目录，不读取应用历史）：

```sh
cd service
node scripts/check-asr-models.mjs --download --models-dir /path/to/model-cache --state-dir /path/to/isolated-state
```

该脚本使用固定公开短样例，依次运行各模型并记录加载、识别和内存数据。它不调用整理模型，不表示准确率排名。完整状态见 `docs/v1.5.0-验证记录.md`。

**整理流水线 `service.polish()`**：空文本→退出；`off`→只 `tidy`；没有可用路由（没 Key）→只 `tidy`；否则 `buildContext`（脱敏上下文）→ 提示词模式时 `refreshPromptify()`（文件被手动改过就重读）→ `systemPromptFor` → `redactSecrets(原话)` → `completeOpenAI` → `parsePolishOutput` → `tidy` → `validateOutput`，不通过或出错都退回 `tidy(原话)`，`fallback: true` 并记原因。提示词模式 `max_tokens ≥ 1600`、超时 ≥ 25 秒。

**翻译走 `polishTranslate()`**：请求带 `translateTo`（`x-voice-translate` 头，或 `/polish` 请求体）时，不管整理档位，只要有路由就一次调用完成整理加翻译；校验用 `validateOutput(strength:"translate")`，只按数值比对数字（`translationInventedNumbers`），不查语言变化；没 Key 或失败都退回 `tidy(原话)`。结果带 `translated`。

**语言变体**：`x-voice-variants`（或请求体 `variants`）在 `recordAndReturn()` 里最后一步转换中文，所以历史和返回的文字一致，原话转写档也生效；英式拼写是加在系统提示词末尾的一句。

**提示词 Beta（`promptbeta`）走 `polishBeta()`**：录音没内容（`hasContent`）→ `empty-transcript`；采访（JSON 规格 + 最多 4 个问题）→ 有问题就存会话（`betaSessions`，15 分钟、最多 20 个，用一次即删），返回 `{text:"", beta:{sessionId, questions}}`，不记历史；客户端下一次听写带 `x-voice-beta-session` 头作为回答（回答没内容当作跳过），或调 `POST /prompts/beta/finish` 跳过；然后起草 → 独立审查（只诊断，JSON issues）→ 有问题才最小修补 → 按 `promptify` 规则校验原话 + 回答，修补不通过而草稿通过就用草稿，都不通过退回 `tidy`。会话过期返回 HTTP 410 `beta-expired`。每次调用超时 ≥ 60 秒，客户端这一档的请求超时 ≥ 300 秒。

**HTTP 接口**（都要 `Authorization: Bearer <token>`，token 和端口在状态目录的 `runtime.json`）：
`GET /health` · `POST /dictate`（WAV → 识别 + 整理）· `POST /polish`（文本 → 整理）· `GET /history` · `POST /learn` · `GET|PUT /dictionary` · `POST /models/download` · `POST /test-llm` · `GET|PUT /prompts/promptify` · `POST /prompts/beta/finish` · `POST /prompts/beta/cancel`

**请求头**：`x-voice-llm`（base64 JSON：baseURL、model、apiKey）、`x-voice-strength`（客户端只发 `off` / `prompt` / `promptify` / `promptbeta`；服务的 `STRENGTHS` 还保留旧档位 `conservative`、`maximal`）、`x-voice-language`、`x-voice-app`、`x-voice-context`（base64 JSON：光标前后文、选中、窗口标题）、`x-voice-beta-session`（提示词 Beta 回答问题时带上）、`x-voice-translate`（翻译目标语言）、`x-voice-variants`（`zh=hans|tw|hk,en=us|gb`）。

**状态目录**：Mac `~/Library/Application Support/TypeLeast/`，Windows `%APPDATA%\TypeLeast\`（模型在 `%LOCALAPPDATA%\TypeLeast\models`）。文件：`runtime.json`、`api-token`、`history.jsonl`、`dictionary.json`、`promptify.json`（`appendix` 追加、`override` 替换，可手动编辑，下次整理生效）、`models/`。

## 4. Mac 客户端：模块与耦合

- **中枢是 `AppDelegate`**（分在 `AppDelegate.swift`、`+Dictation.swift`、`+Update.swift` 三个文件），它实现 `AppActions`（界面调用）和 `MenuActionTarget`（菜单调用）两个协议，持有 `MenuController`、`Recorder`、`ServiceClient`、`ServiceManager`、录音条等。
- **界面是 SwiftUI**：`HubWindow`（主窗口）→ `HubPages`（首页 / 历史 / 词典）、`HubSettings`（设置；所有开关走 `ToggleRow` + `StateSwitchStyle`，开绿关灰）、`PromptifySettings`（提示词模式：默认锁定、追加、两次警告 + 6 位验证码才能改默认、恢复默认）。界面只通过 `AppModel.shared`（`ObservableObject`）读状态、通过 `model.actions?` 调 `AppDelegate`。
- **设置**：`Settings`（UserDefaults，键名带 `voice.` / `llm.` 前缀，bundle id 仍是历史遗留的 `com.dsh.voice`，**不要改**，改了会丢设置和权限）。`LLMSettings.swift` 里有服务商预设 `LLMPreset`、`KeychainStore`（服务名 `TypeLeast.llm-api-key`，账户名是预设 id；测试里必须设 `KeychainStore.stub`，否则会读真实钥匙串并弹窗）。
- **听写状态机** `AppDelegate+Dictation.swift`：`idle → recording → thinking → idle`；开始提示音是 `StartChime`（合成的 E6→B6 两声），结束是系统 Pop。
- **提示词 Beta**：有问题时 `BetaPanel`（右上角不抢焦点的浮窗）列出问题，`betaPending` 记住原来的 App 和输入框；下一次听写作为回答，结果贴回原输入框。改了整理档位就丢弃待回答的问题。
- **菜单栏** `MainMenu`：应用自己的主菜单（TypeLeast / 编辑 / 窗口）。没有它时切到主窗口，左上角仍显示上一个应用的菜单，输入框的 ⌘C / ⌘V 也不工作（AppKit 通过主菜单分发这些快捷键）。状态栏图标的菜单是另一个：`MenuController`。
- **翻译与活动**：翻译快捷键（槽位 `translate`，默认 ⇧⌥Space，不能是 Fn）开始的录音带 `pendingTranslate`，录音条显示「→EN」，不会被当成提示词 Beta 的回答。`ActivityLog`（UserDefaults `voice.activity.v1`）按天只记次数和字数，首次启动从现有历史补数据，「删除全部历史」一并清空；首页 `ActivityCard` 画热力图。
- **服务通信** `ServiceClient`（同步 HTTP，读 `runtime.json`），`ServiceManager` 负责找 Node.js（App 内置 > 系统）并启动服务。
- **插入**：`Inserter`（剪贴板 + 合成 ⌘V，事后恢复剪贴板，切了窗口就不粘贴）。`FieldContext` 读光标上下文（辅助功能 API），`EditLearner` 从用户改动里学词。
- **热键**：`HotKey`（Carbon 热键）+ `FnKey`（单按 Fn）。
- **更新** `Updater.swift` + `AppDelegate+Update.swift`：用本机 `gh` 的登录从私有仓库下载最新 Release 的 zip → 核对 SHA256SUMS.txt → 用本机证书「TypeLeast Local Signing」重签 → 比对签名要求与当前一致 → 退出后替换并重启。只在装了 gh 且有本机证书的 Mac 上可用。

## 5. Windows 客户端

`TypeLeast.Core`（可测试）：`ServiceClient`、`ServiceLocator`（找 Node）、`AppSettings`、`LocalHistory`、`LlmPresets`、`TapDetector`、`Models`（含 `PromptifySettings`、`PromptifyGuard`）。
`TypeLeast`（WPF）：`AppHost`（中枢，对应 Mac 的 AppDelegate）、`KeyboardHook`、`AudioRecorder`（NAudio）、`Paster`、`Tray`、`ServiceManager`、`Ui/`（`MainWindow`、`SettingsPage`、`PromptifyPanel`、`RecordingBar`、`Theme`）。
Windows 的翻译键是第二个单击键（`KeyboardHook` 里第二个 `TapDetector`，默认关闭，不能和听写键相同）；活动记录在 `app-activity.json`（`ActivityLog`），首页 `Ui/ActivityView.cs` 画最近 26 周。
Windows 版的提示词模式界面和提示词 Beta 问题窗（`Ui/BetaPanel.cs`，`AppHost` 里的 `ShowBetaQuestions` / `DropBeta`）**只在 CI 上编译和跑过单元测试，没在真机上点过**。

## 9. 改代码时的约束

- 自然整理只使用 `service/lib/prompts/cleanup.js` 中维护者提供的提示词，不再保留或加载旧自然整理提示词。正文按维护者提供的内容保留；词典和光标上下文在独立附录中添加。修改实际发给模型的提示词时同步更新 `PROMPT_VERSION` 和相关测试。
- 改了服务接口：同时改 `ServiceClient.swift`、`TypeLeast.Core/ServiceClient.cs` 和两边测试。
- Mac 新增设置开关一律用 `ToggleRow`。
- 测试里不得读真实钥匙串、不得用真实听写内容、不得写真实路径或用户名（用 `/Users/someone`、`sk-test-…` 这类假值）。
- 提交、PR、发布流程见维护者的「GitHub 提交规则」：分支 → PR → CI 全过 → 快进合并；不强推；每次发布写 CHANGELOG 和 `.github/release-notes.md`。


## 10. 界面语言与隐私检查（1.4.0）

- Mac `L10n.swift` 和 Windows Core `L10n.cs` 集中管理中英文界面文字；中文原文为查找键，动态内容通过参数传入，不对用户文本做翻译查找。
- 独立界面语言设置：`system` / `zh-Hans` / `en`，重启生效。中文系统默认简体中文，其余默认英语；听写语言独立。
- 服务通过现有 `x-voice-language` 接收逐次听写语言，校验后传到识别器；识别任务串行处理，语言改变时重建单个识别器，避免共享配置串扰。
- 模型请求禁止自动重定向。中文显式凭据、词典与光标上下文经过脱敏；错误请求不回显 JSON 片段，桌面诊断不保留原始异常文本。
- `node service/scripts/check-localization.mjs` 检查两端翻译覆盖和格式参数。检查结果及限制见 `docs/检查与验证-1.4.0.md`。


## 安全边界与历史存储（未发布）

- `SelfIntegrity` 在 Mac 服务启动前检查签名和密封资源；构建开启 Hardened Runtime，更新重签保留标志和权限声明。该检查不证明发布者身份，不防止攻击者替换整个 App 并重新签名。
- `InstanceLock` 使用系统文件锁；进程退出时自动释放。隔离测试实例不注册全局快捷键。
- 两端 `ServiceLocator` 优先内置服务，并为 Node 启动和版本探测过滤环境变量；保留企业 CA 的 `NODE_EXTRA_CA_CERTS`。开发覆盖仍可用于没有内置服务的开发环境。
- `HistorySeal` 使用 AES-GCM，独立密钥由钥匙串保存；旧偏好历史与应用临时录音迁移后删除原明文。失败时保留原数据、显示错误，不写入新的明文历史。录音采集与请求期间仍有临时明文 WAV。
- Windows `LocalHistory` 通过可替换的 `IHistoryProtection` 调用当前用户 DPAPI；原生实现仅在 Windows 运行，其他系统的单元测试使用替身。旧 JSON 原子替换为加密数据，损坏或无法解密的文件不会被后续保存覆盖。
- 服务历史 `logRaw` 默认关闭，启动前原子迁移旧文字为摘要，失败时停止启动；显式开启仍保存明文。摘要不能等同于加密，短句可能被猜测。
- `TerminalGuard` 仅对已知终端过滤换行和控制字符，减少意外执行；不识别所有 IDE 内嵌终端，也不审查命令内容。
- 尚未处理：`runtime.json` 所指本地服务的独立身份认证、更新包的独立可信签名。前者需要另行确认接口与服务生命周期方案；本轮没有加入挑战应答协议。

测试与验证结果见 [安全加固验证记录](安全加固验证记录.md)。
