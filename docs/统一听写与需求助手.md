# 统一听写与需求助手

本页描述未发布实现。旧历史中的档位信息保留，当前交互不再选择整理档位。

## 入口与数据边界

- 听写：本机识别，理解整段，保留实质信息并按需要重排、去重复。没有自动摘要档位。
- 翻译：先走同一套原语言整理，再翻译。第一步失败不能绕过检查直接翻译。
- 需求助手：独立按钮和默认未绑定的快捷键；每轮最多 3 个问题，按实际缺口询问，用户主动生成一次。没有固定四题或生成、审查、修补循环。

音频不新增外发。整理提供商只接收本次文字、必要解释、用户允许的光标上下文及相关词典条目。背景资料回答不授予应用搜索、文件读取或任务执行权限。没有恢复个人词汇、自动入词或永久替换。

## HTTP 契约

所有接口沿用本机回环监听、Host 检查、Bearer 鉴权及应用持有的服务身份证明。

| 项目 | 约定 |
|---|---|
| `/polish` JSON `task`、`/dictate` 头 `x-voice-task` | `dictation`、`translation`、`assistant`；显式未知值拒绝 |
| 缺少任务字段 | 普通旧 `strength` 映射听写；`promptbeta` 映射需求助手；已支持的翻译目标仍优先识别为翻译 |
| 翻译目标 | 继续使用 `translateTo` / `x-voice-translate`；显式 translation 必须提供受支持目标 |
| 需求助手继续 | 听写请求携带 assistant 任务及旧会话字段；文本 `/polish` 支持 `betaSession` |
| 主动生成 / 取消 | `POST /assistant/finish`、`POST /assistant/cancel`，保留旧 `/prompts/beta/*` 别名 |
| 响应 `task` | 当前任务；旧 `beta`、`strength` 和 clarification 字段仍可兼容读取 |
| `GET /tasks/progress?id=...` | 经鉴权返回 stage、completed、total；不返回正文、路径、路由或凭据 |

客户端每次音频请求生成随机请求 ID，只有处理期间轮询进度。服务最多保存 20 条进度状态，10 分钟后失效。进度不会写入用户正文日志。

## 长口述与交付

录音上限 600 秒、标准单声道 16 kHz PCM、音频上限 24 MiB；客户端请求等待覆盖最长 300 秒识别、180 秒整理及传输余量。ASR 顺序处理分段并保留位置，尾部不足一个 VAD 窗口时补零送入，不丢尾部。原生解码的取消在返回或分段边界检查，独立模型子进程可以终止并在下一次请求重建。

正文上限为 32000 个 Unicode 字符。普通生成默认一次，输出上限按输入增长至最多 8192 tokens，温度 0.3。超过 6000 字符或遇到明确的提供商上下文限制时进入分块；每块目标不超过 2500 字符，按句末优先切分且不丢字符。先提取带原文引用的名称、改口和跨段约束，引用不成立则停止。各块串行处理，共享同一份依据，合并后对照全文检查。

生成、兼容重试、分块和完整性检查共用 180 秒及一次暂态技术重试额度。`stream:false` 表示完整响应后解析与检查；阶段反馈单独实现。截断、格式错误、事实或完整性检查失败不能作为成功输出。提供商无法处理输入或输出规模时保留内容并报告限制，不静默截断。

当前明确解释或逐字拼写可以支持名称纠正；类别、相似读音和过去偏好不能单独授权改名。名称审查不能绕过数值和语言检查。合理去重复和明确改口导致的缩短，可以经完整性检查通过，不以长度比例独断。

失败响应 `text` 为空，候选只放在 `clarification.candidate`。非模态恢复面板默认收起编辑区，提供重试、查看修改、使用识别原文和取消。手工确认的文字直接交付，仍保留目标窗口及剪贴板保护。取消后的迟到响应不能粘贴。

## 兼容与验证

设置迁移只执行一次；需求助手不再写成持久整理档位。历史新增可选任务字段，旧记录保持原档位元数据。现有表达示例、历史、录音、模型、凭据和风格包不因本次重构删除。

开发者运行 HTTP 契约 v3 与假 ASR 契约 v3；旧客户端契约继续检查历史字段兼容。单元回归、假 ASR、真实模型文字测试和真实语音识别质量分别报告，不能相互替代。测试与渲染入口不进入安装包。
